# Synthetic calibration fixtures

No real probe logs were supplied for this build. Nothing in this repository is empirically calibrated.

`fixtures/synthetic_calibration.json` contains two deterministic pseudo-experiments generated by the NumPy solver itself on 21³ grids. Their names start with `synthetic-`, provenance is embedded in the file, and their generating parameters are included:

- roast, still/open: `h_conv=10 W/m²K`, emissivity 0.90, reservoir 0.25 kg/m²;
- slab, fan/covered: `h_conv=20 W/m²K`, emissivity 0.90, reservoir 0.25 kg/m².

Regenerate them with:

```bash
python fixtures/generate_synthetic_calibration.py
```

These fixtures exercise file shape, sampling, wet/covered staging, and future fitting code. Because inverse-crime data come from the same solver and contain no experimental noise or geometry mismatch, parameter recovery from them would demonstrate plumbing only—not identifiability or predictive accuracy. They are never presented in the UI as observed cooks.

## Future real-log contract

A real calibration dataset should preserve, at minimum:

- timestamped calibrated probe temperature(s), probe location and insertion uncertainty;
- measured oven air and preferably wall/radiant temperature histories;
- mass before/after, dimensions or SDF source, preset/cut/species, cover/fan and pan state;
- initial equilibration, ambient rest conditions, and pull timestamp;
- instrument IDs, uncertainty, missing samples, and provenance/consent.

Fit training cooks separately from held-out validation cooks. Candidate fitted parameters are preset-level convection, emissivity, and surface reservoir; avoid fitting all three from a single center curve without surface or mass-loss observations because they are strongly confounded. Report posterior/interval uncertainty and retain analytic tests regardless of fit quality.

Published tables are broad plausibility references, not synthetic probe logs and not silently treated as empirical calibration data.
