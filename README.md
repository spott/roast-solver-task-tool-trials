# Roast Solver

A locally hostable first web-app version of the 3-D roast heat-transfer model in [`PROJECT_PLAN.md`](PROJECT_PLAN.md), implemented through **M6**. It includes a NumPy reference solver, a dependency-free Rust/WASM port, progressive worker execution, and a static browser UI.

> **Accuracy status:** this is an uncalibrated physics preview. No probe logs were provided. The included “calibration” data are plainly labeled synthetic fixtures generated by this repository. Do not substitute a prediction for a calibrated thermometer or current food-safety guidance.

## What is included

- Temperature-dependent Choi–Okos component properties bounded to the lean-meat bulk range.
- One SDF interface for mass-normalized roast, composed bird with cavity/appendages, rounded slab, and ham presets.
- Conservative 3-D, seven-point explicit conduction and lagged properties.
- Embedded coarea surface cells, local Robin ghost-surface temperatures, pan-contact insulation, and energy accounting.
- Convection, nonlinear radiation, Lewis-analogy evaporation, independent surface-cell moisture/crust stages, covered mode, and ambient rest/carryover.
- Coldest/deep-probe curves, pull and rest peak, doneness slices, water loss, and a conservative 70°C / z=10°C pasteurization integral.
- Rust core with a raw browser ABI, Python-generated scenario goldens, and progressive stepping in a Web Worker.
- Zero-runtime-dependency static UI and reproducible Nix build.

M7 WebGPU and M8 photo reconstruction are intentionally absent.

## Quick start with Nix

```bash
nix develop path:.
pytest -q
cargo test --manifest-path rust-core/Cargo.toml
npm --prefix web test
npm --prefix web run build
npm --prefix web run preview
```

Open <http://127.0.0.1:4173>. `path:.` lets Nix see an uncommitted worktree; after the files are tracked, ordinary `nix develop` also works.

A one-command reproducible production build is:

```bash
nix build path:.#default
npx serve -s result             # or any static server
```

The flake output is only HTML/CSS/JS/WASM. It has no backend.

## Without Nix

Install Python 3.11+, NumPy, pytest, Node 20+, Rust/Cargo, `lld`, and the `wasm32-unknown-unknown` Rust target. Then:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
pytest
cargo test --manifest-path rust-core/Cargo.toml
npm --prefix web test
npm --prefix web run build
npm --prefix web run preview
```

Run the reference model directly:

```bash
roast-solver --preset roast --mass 1.5 --oven 180 --target 57 \
  --convection --output run.npz
```

The default reference grid is 41³. Increase it for studies; explicit runtime scales approximately with voxel count times step count.

## Static hosting

Upload the contents of `web/dist/` (manual build) or `result/` (Nix build) to GitHub Pages, Netlify, S3, nginx, Caddy, or another static host. Requirements:

1. serve `roast_core.wasm` as `application/wasm` (the worker has a non-streaming fallback, but the MIME is recommended);
2. preserve the four files next to `index.html`; and
3. use HTTP(S), not `file://`, because workers and WASM fetches are browser-origin resources.

No special routing, server functions, cross-origin isolation, or database is required.

## Repository map

| Path | Role |
|---|---|
| `roast_solver/` | authoritative NumPy properties, SDF, boundary physics, analytics, solver, CLI |
| `tests/` | M1–M4 unit, convergence, Robin sphere, energy, and rest validation |
| `rust-core/` | native-testable Rust kernel and raw WASM exports |
| `fixtures/` | generated Python→Rust goldens and explicitly synthetic pseudo-probe fixtures |
| `web/` | production static application and progressive worker |
| `docs/PHYSICS.md` | equations, discretization, assumptions, and outputs |
| `docs/VALIDATION.md` | validation scope, commands, tolerances, and measured limitations |
| `docs/CALIBRATION.md` | synthetic fixture provenance and future real-log contract |
